# Лабораторная работа № 1. Алгоритмы сортировки

## Цель работы

Познакомиться с анализом алгоритмов на примере сортировки.
Реализовать два разных алгоритма на C++, оценить время работы и расход памяти.

## 1. Сортировка подсчетом

### 1.1. Постановка задачи

После тестирования получен список баллов студентов. Каждый балл — целое число
от 0 до 100. Нужно расположить баллы по возрастанию. Сортируются только числа,
без фамилий и других связанных данных.

Вход: количество студентов n (от 1 до 100000) и n баллов.
Выход: те же баллы по возрастанию с сохранением всех повторений.

Пример входа:

```text
7
90 60 100 60 0 75 90
```

Результат:

```text
0 60 60 75 90 90 100
```

### 1.2. Выбор алгоритма и расчет затрат

Выбрана сортировка подсчетом. Создаем массив из 101 счетчика. Для каждого
балла увеличиваем соответствующий счетчик. Затем перебираем баллы от 0 до 100
и записываем каждый в исходный массив столько раз, сколько он встретился.

После подсчета count[x] равен количеству баллов x. При восстановлении значения
перебираются по возрастанию, поэтому результат упорядочен, а количество
каждого значения остается прежним.

Обозначим число возможных значений через k = 101. Основные действия:

- обнуление счетчиков — k записей;
- подсчет баллов — n увеличений счетчика;
- просмотр счетчиков — k шагов;
- запись результата — суммарно n записей, несмотря на вложенные циклы.

Таким образом, объем этих действий равен 2n + 2k. Это не точное число всех
машинных инструкций: проверки циклов и изменения индексов тоже требуют времени.
Итоговая временная сложность — Θ(n + k). При k = 101 она равна Θ(n)
в лучшем, среднем и худшем случаях. При n = 1000 получаем 2202 перечисленных действия.

Дополнительная память — k целых чисел и несколько переменных, то есть O(k).
При фиксированном k это O(1). Если int занимает 4 байта, счетчики занимают
404 байта. Данные исходного массива занимают 4n байт; вместе с ними — примерно
4n + 404 байта, без учета служебных данных vector и отдельных переменных.

Для этой задачи выбор асимптотически оптимален: любой алгоритм должен
прочитать все n баллов, а значит, требует не менее Ω(n) времени.
Подсчет достигает этой границы и использует небольшой фиксированный массив.
Сортировки сравнением общего назначения обычно требуют O(n log n) или O(n²)
в худшем случае. Преимущество подсчета здесь обеспечено узким диапазоном баллов;
для произвольных целых чисел этот аргумент уже не подходит.

### 1.3. Реализация

Файл `task1.cpp`. Функция `countingSort` сортирует массив на месте,
используя счетчики. В `main` проверяется количество и диапазон баллов.

## 2. Сортировка вставками

### 2.1. Постановка задачи

Есть небольшой список целочисленных результатов измерений, обычно уже почти
отсортированный. После добавления или исправления нескольких значений нужно
снова расположить его по возрастанию. Значения могут быть отрицательными,
повторяться и иметь большой разброс. Желательно обойтись без второго массива.

Вход: количество измерений n (от 1 до 1000) и n значений, помещающихся в int.
Выход: те же значения по возрастанию. Программа также должна правильно работать
для полностью неупорядоченного списка.

Пример входа:

```text
6
-10 0 20 15 30 25
```

Результат:

```text
-10 0 15 20 25 30
```

### 2.2. Выбор алгоритма и расчет затрат

Выбрана сортировка вставками. Сначала первый элемент считается отсортированным.
Каждый следующий элемент временно сохраняется. Большие элементы слева сдвигаются
на одну позицию вправо, и сохраненное значение вставляется на свободное место.

Перед шагом i первые i элементов упорядочены. Сдвиг только больших значений
и вставка текущего элемента сохраняют порядок этой части, увеличивая ее на один
элемент. После последнего шага упорядочен весь массив, ни одно значение не потеряно.
Равные элементы не сдвигаются друг относительно друга, поэтому сортировка устойчива.

В лучшем случае массив уже отсортирован. Выполняется n − 1 сравнение значений,
сдвигов нет. Время — Θ(n).

В худшем случае все значения различны и идут по убыванию. На шаге i выполняется
i сравнений значений и i сдвигов. Общее число сравнений значений:

```text
1 + 2 + ... + (n − 1) = n(n − 1) / 2.
```

Число сдвигов такое же. Дополнительно выполняется n − 1 запись сохраненного
значения на найденную позицию. Для n = 1000 это 499500 сравнений значений,
499500 сдвигов и 999 завершающих записей. Проверки индексов считаются отдельно
и не меняют порядок роста. Худшее время — Θ(n²).

Для случайной перестановки различных значений среднее число сдвигов равно
n(n − 1) / 4, поэтому среднее время — Θ(n²).

Для почти отсортированного массива удобно считать число инверсий I — пар,
в которых большее значение стоит раньше меньшего. Каждый сдвиг устраняет
одну инверсию, поэтому время составляет Θ(n + I). Если I = O(n), получаем Θ(n).

Дополнительная память — только переменные i, j и value: O(1), без рекурсии
и вспомогательного массива. При четырехбайтовом int это примерно 12 байт
для этих переменных. Сами данные занимают 4n байт, полная память — O(n).

Вставки подходят под выбранные условия: небольшой размер, мало инверсий,
произвольный диапазон значений и постоянная дополнительная память.
При I = O(n) время линейно, что асимптотически оптимально с учетом необходимости
просмотреть вход. Подсчет неудобен из-за большого диапазона, выбор всегда делает
квадратичное число сравнений, а обычное слияние требует дополнительного массива.
Это обоснование выбора для данной задачи, а не утверждение, что вставки быстрее
всех алгоритмов на любом входе. Для больших неупорядоченных массивов предпочтительнее
алгоритмы с гарантированным O(n log n).

## 3. Сравнение

| Свойство | Подсчет, k = 101 | Вставки |
| --- | --- | --- |
| Лучшее время | Θ(n) | Θ(n) |
| Среднее время | Θ(n) | Θ(n²) для случайной перестановки |
| Худшее время | Θ(n) | Θ(n²) |
| Дополнительная память | O(1) при фиксированном k | O(1) |
| Значения | Целые от 0 до 100 | Любые значения int |

Условие задания выполнено: алгоритмы различаются, а худшая временная сложность
второго, Θ(n²), выше сложности первого, Θ(n). Ограничения количества элементов
в программах нужны для удобства запуска; при анализе n рассматривается как
изменяемый размер задачи.

## Вывод

Выбор сортировки зависит от свойств данных. Для баллов с небольшим диапазоном
выгоден подсчет, а для небольшого почти упорядоченного списка подходят вставки.
Обе реализации используют обычные циклы, функции и vector для хранения чисел.
Готовые функции сортировки не используются.
